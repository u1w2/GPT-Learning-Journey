# Stage 01｜工程基础与架构思维起点

> 本阶段不是重新学习编程语言，而是把已有项目经验转化为可分析、可验证、可解释、可迁移的工程能力。

## 阶段目标

完成本阶段后，学习者应能够：

- 从业务目标拆解系统需求。
- 区分功能需求与非功能需求。
- 描述系统边界、核心组件和关键数据流。
- 对容量、性能、可靠性和成本提出基本假设。
- 用实验而不是感觉验证系统能力。
- 主动制造并复现项目短板。
- 解释问题的根因、解决方案和 Trade-off。
- 将项目经验迁移到新的业务场景。
- 用清晰结构进行项目答辩。

## 第一阶段能力域

### 01. 工程问题建模

把模糊需求转化为业务目标、约束、输入、输出和验收标准。

### 02. 系统拆解

能够识别边界、组件、依赖、数据流和关键状态。

### 03. 非功能需求

初步建立性能、容量、可用性、一致性、安全、可观测性和成本意识。

### 04. 验证与测试思维

学习如何设计实验来验证假设、寻找瓶颈和确定能力边界。工具不绑定业务语言，Python 可作为通用实验语言。

### 05. 架构表达

能够解释“为什么这样设计”，而不是只描述“用了什么技术”。

### 06. 问题复盘

能够把一次故障或短板转化为可迁移的经验。

## 阶段项目要求

第一阶段项目必须包含：

- 完整业务场景
- 架构设计
- 可运行实现
- Test Lab
- 至少一个能力边界实验
- 至少一个可复现问题
- Root Cause 分析
- 至少两种解决方案比较
- Architecture Decision
- Limitations
- Experience Card
- Interview Project Defense

## 阶段验收

不能以“代码运行成功”作为通过条件。必须能够：

1. 解释系统为什么这样设计。
2. 通过实验说明系统能做到什么程度。
3. 复现至少一个问题。
4. 独立分析根因。
5. 解释至少两种解决方式的 Trade-off。
6. 说明当前方案的局限。
7. 将经验迁移到一个新的业务场景。
8. 经 AI 面试官追问后仍能保持逻辑完整。

## 注意

本阶段具体任务和项目将根据基线诊断结果确定。不要提前假设用户缺什么，也不要把所有内容一次性灌输。
