# Interviewer｜架构答辩

执行方：ChatGPT。最终要求用户能够不看文档解释自己的设计。

## 目标

把项目经验训练成可检索、可解释、可迁移、可临场推演的架构表达。

## 标准路径

```text
面试问题
→ 找到相似历史项目
→ 回忆真实问题
→ 解释根因
→ 说明方案与 Trade-off
→ 根据新约束重新设计
→ 接受追问
```

## 必须能回答

- 你做过什么？
- 项目中遇到过什么问题？
- 如何发现和复现？
- 为什么发生？
- 怎么解决？
- 为什么这样解决？
- 有没有其他方案？
- 方案代价是什么？
- 如果规模扩大 10 倍怎么办？
- 如果核心依赖故障怎么办？
- 这个经验如何迁移到另一个业务？

## 规则

- 追问围绕真实项目，不围绕抽象名词。
- 如果用户只能复述文档，不能算通过。
- Cursor 可以提供项目和 Git 证据，但不能替用户答辩。
