# Capability Edge｜找边缘、清晰化、再扩展

本协议服务用户的真实目标，而不是把 10 个 curriculum 目录上完。

## 目标

```text
找到能力边缘
    ↓
把模糊部分清晰化（强化）
    ↓
适当扩展
    ↓
成为能独立做系统架构、并具备 AI 系统设计经验的高级架构全栈师
```

## 每次作答后只分三类

| 标记 | 含义 | 下一步 |
| --- | --- | --- |
| Sharp | 能说清为什么、替代方案、代价、何时推翻 | 保持，作为可迁移模式 |
| Fuzzy | 有直觉，但说不清边界，或把未来当成现在 | **下一题就打这里** |
| Blind | 这轮根本没看见这个维度 | 记录，但不立刻开新课 |

找不到边缘，训练就没有意义。
把 10 个阶段按顺序学完，也不等于成为架构师。

## 强化优先于扩展

只有同时满足，才允许扩展到新领域：

1. 当前主模糊点已经能独立讲清。
2. 能迁移到一个稍不同的场景。
3. 最好有项目或实验证据，而不是只改口。

未满足时，继续打当前 Fuzzy。不要因为“高级架构师还要会 K8s / Agent”就提前开课。

## 当前已看见的边缘

主 Fuzzy：会担心以后重构，但还不能稳定区分“现在必须冻结”和“现在必须延后”。

所以当前题是 API Question 1，不是分布式，也不是 AI Agent。

## 通向终局的扩展顺序

终局不是“先成为传统架构师，最后再学 AI”。AI 是同一套架构判断迁移到模型组件上。

但扩展仍然要有约束：

```text
全栈契约（Web / 小程序 / 后台 / 以后可能的 Agent 客户端）
    ↓
系统与数据设计
    ↓
可靠性 / 演进 / 故障
    ↓
把模型当系统组件：评测、降级、责任边界、数据闭环
```

在 API 判断还模糊时，不进入 Stage 09/10 的专门训练。
可以在当前题里问一句：如果以后多一个 AI 客户端来调这个 API，会不会改变“现在必须定什么”。这是探测，不是开 AI 课。
