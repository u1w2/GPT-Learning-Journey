# Reinforce｜项目能力评判与跨周期强化

这个机制回答两件事：

1. 每个项目必须留下针对个人的能力记录和评判。
2. 项目结束后，下一个周期在学新内容的同时，必须带回未关闭缺陷做再次强化。

## 为什么要这样做

只向前学新阶段，缺陷会被新知识盖住。
架构能力不是背名词，强化必须是：

```text
同一个判断
    ↓
放到新场景里再做一次
    ↓
不看旧文档还能讲清
    ↓
才能从 Fuzzy 变成 Sharp
```

所以“增加记忆强化轮数”在这里不是闪卡，而是 **新情境复测轮数**。

## 每个项目结束时必须产出

1. `capability-review/`：这次项目里，个人哪些 Sharp / Fuzzy / Blind
2. 更新 `learner/capability.md`：有证据才改等级
3. 更新 `learner/defects.md`：新缺陷入库，旧缺陷记一轮复测结果
4. 下一周期任务里写明：要带着哪些缺陷一起打

没有个人评判的项目，不算完成。
下一周期如果不带回 Open 缺陷，也不允许只开新课。

## 缺陷轮次

| 轮次 | 名称 | 要求 |
| --- | --- | --- |
| R1 | Probe | 第一次暴露这条模糊/错误 |
| R2 | Near Transfer | 下一个周期，用稍不同的场景再做一次 |
| R3 | Far Transfer 或 Unaided Defense | 换领域迁移，或不看文档讲清 |

默认 Open 缺陷至少 3 轮。R1 通过不算掌握。必须在新周期再打中，才能关闭。

## 关闭条件

同时满足才关闭：

- 至少完成 R2
- 新场景下标记为 Sharp
- 能说出为什么、替代方案、代价
- 最好有项目或实验证据

只是“这回改口了”，保持 Open，并增加一轮。

## 和学习新内容的关系

```text
新周期内容（扩展）
        +
未关闭缺陷（强化）
        ↓
同一个项目 / 同一组题里一起出现
```

例如：下一周期如果进入缓存，题目里必须再次出现“现在必须定还是必须延后”。不是先把 API 课结束，以后再复习。

## 数量限制

同时 Open 的主缺陷不超过 3 条。
下一周期只强制带回优先级最高的 1–2 条。
否则会变成缺陷清单，而不是训练。
