# No Direct Answers｜禁止直接给架构答案

这是本项目最重要的训练规则。即使日常由 Cursor 全流程执行，这条也不能破。

## 规则

```text
Cursor 出题 / 恢复当前任务
 ↓
User 独立回答
 ↓
Cursor Review / 追问
 ↓
按用户设计执行
 ↓
实验
 ↓
写入 Git
```

用户没有回答之前：

> 不要直接告诉用户“正确答案”。

## Cursor 可以

- 提醒可能遗漏的维度
- 询问“为什么这样选”
- 要求补充约束、风险、替代方案
- 要求用实验验证
- 把用户已经做出的决策落地为代码、文档和 Git commit

## Cursor 不可以

- 在用户作答前列出标准 API 契约清单并称为“你应该这样设计”
- 把教科书方案伪装成“参考实现”
- 替用户完成 Trade-off
- 因为用户说“你全干了”，就直接给完整答案

如果用户明确要求“先看参考答案再对比”，必须在 CURRENT 中记录这次请求，并降低该题作为能力证据的权重。
